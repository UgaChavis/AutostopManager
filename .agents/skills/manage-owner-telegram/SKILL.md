# Управление Telegram владельца

Перед любой операцией полностью прочитать `/opt/AutostopManager/docs/agent/telegram_workflow_playbook.md`. Считать его каноническим источником команд, границ доступа и восстановления.

## Рабочий порядок

1. Проверить `autostop-telegram.service` и `status`; не открывать SQLite-сессию вторым Telethon-клиентом при работающем daemon.
2. Для общего обзора использовать `dialogs` с малым лимитом. Для имени использовать `search`, затем работать по положительному или отрицательному числовому `peer id`.
3. Читать только нужный диалог и ограниченное число сообщений. Пересказывать результат; не копировать полные переписки.
4. Отправлять только по прямому заданию владельца для конкретного получателя и понятного текста или намерения:
   - найти кандидатов;
   - выбрать ровно один точный `peer id` и перечитать его;
   - выполнить `send --mode dry_run`;
   - выполнить `apply` с тем же текстом, contract token и новым idempotency key;
   - независимо перечитать диалог и проверить исходящее сообщение.
5. Если ответ потерян или истёк timeout, не повторять отправку: сначала искать точное исходящее сообщение. Повтор допустим только после подтверждённого отсутствия.
6. Для явно порученного фото использовать только один service-owned JPEG mode
   `0600` из `/run/autostop-telegram/outbox`: `send-photo` dry-run, затем apply
   с неизменными peer/caption/hash, новым idempotency key и независимым чтением.
   После подтверждённой доставки удалить точную staged-копию.

## Жёсткие ограничения

- Не выводить и не сохранять `api_hash`, QR URL/token, 2FA, login code, `.session`, contract token, VPN URL/profile или полный экспорт сообщений.
- Не сохранять Telegram-контент в Manager memory, docs, Git, workflow ledger или обучающие данные. Допустимы только обезличенные технические правила и результаты проверки.
- Не отправлять, удалять, редактировать, пересылать, вступать/выходить, блокировать, читать историю массово или менять read state без точного текущего поручения владельца.
- При неоднозначном имени не угадывать по username, аватару или последней активности; показать безопасные различия или запросить выбор.
- Не использовать личную сессию параллельно из другого процесса или хоста.
- Не менять default route, DNS, CRM-сети или VPN ради Telegram.

## Авторизация

QR краткоживущий. Показывать только свежий атомарно записанный PNG под новым именем, ждать до `expires`, а не обновлять заранее. 2FA получать только через приватный одноразовый файл, который мост удаляет сразу после чтения. После успеха удалить QR-файлы, включить daemon и проверить `status`, `dialogs` и повторный запуск сервиса.
