# Управление Telegram владельца

Перед любой операцией полностью прочитать
`/opt/AutostopManager/docs/agent/telegram_workflow_playbook.md`. Это единственный
подробный владелец команд, границ доступа, авторизации и восстановления.

## Рабочий порядок

1. Явно выбрать `personal` или `work`, использовать только его работающий
   daemon и проверить `probe`, затем определить один точный live peer через
   ограниченный `search`.
2. Читать минимальное окно. Вложение скачивать только по точным peer/message:
   dry-run, apply с новым idempotency key, проверка, локальный разбор и удаление.
   Для аудио и видео запускать помощник только с явным
   `--account personal|work`: он сам привязывает файл к private inbox выбранного
   профиля и не принимает ручной путь к модели.
3. Отправлять только по прямому поручению владельца. Всегда выполнять точное
   перечитывание, dry-run, apply и независимый readback.
4. После timeout сначала искать уже отправленное сообщение; не дублировать его.
5. Telegram-контент и идентификаторы держать только в текущем выполнении.

## Жёсткие ограничения

- Не выводить и не сохранять секреты, токены, сессию, полный экспорт или
  Telegram-контент; медиа не исполнять и не отправлять во внешний сервис.
- Не делать массовое чтение и не менять Telegram-состояние вне точного
  поручения.
- Не угадывать неоднозначного адресата. Не использовать сессию параллельно.
- Для первого входа `work` использовать только скрытый интерактивный ввод
  кода/2FA на контролируемой консоли; не переносить `tdata`, сессию, QR или код
  в чат.
- Не менять VPN, DNS, default route или CRM-сети ради Telegram.
