# Повторное независимое ревью клиентского пакета

Проверены полные изменения Manager
`c3b49a7e432c856ff514802950f16f61cddaf588..d9e41e8c45b3d75b82bc12fabdbad0afa57f8b5d`
и CRM `60b4ca39e841269e8c1eb5a4f25e1c8472c9458f..6bc1bbae9166b7b170dbfac6aed44bded3a04dba`.
Три независимых ревьюера прочитали исходное поручение и соответствующие инструкции,
проверили исходники и реальные локальные handlers; прежние отчёты до собственного
анализа не использовались. Проверки выполнялись на синтетических данных с запрещённой
внешней сетью. Live Telegram/CRM, Store, службы и рабочая конфигурация не менялись.

## Исправления и проверка

Исправления выполнены отдельными авторами и возвращены исходным независимым ревьюерам.

- Прямые рабочие text/photo/document проверяют реального peer, паузу, pending guidance
  и unknown ledger до нового intent; исходный receipt остаётся доступен без resend.
  Owner fingerprint сверяется с запрашиваемым peer, а не новым значением owner config.
- Started failed ход остаётся на сверке: пустой Telegram ledger не исключает CRM-запись.
  Автовосстановление допускает только доказанный `not_started`. Resume также не
  освобождает failed parked turn. Старые unsafe failed-waiter записи при migration
  переходят на сверку; уже завершённые факты не переигрываются.
- Inbox schema 5 сохраняет количество pending guidance без текста. Pause/takeover/resume
  не удаляют принятый набор, переполнение явно отклоняется до изменения revision.
  Утраченный transient набор восстанавливается явно через trusted `recover_guidance`
  со свежим CAS. Недоступное указание нельзя обойти пустым `already_answered`:
  bridge и inbox требуют переданный verified result/handoff receipt того же job;
  ACK и пустой список не доказывают ответа. Поздний реальный результат сохраняется.
- Source failures имеют общий класс/исходную причину и проверенную входную привязку;
  пустой native отказ сохраняется диагностикой, а не конфликтом пригодного профиля.
  Совпавший VIN digest не скрывает чужой/повреждённый WMI ни в одном carrier;
  frame/WMI, реальные факты/конфликты и caller downgrade остаются под проверкой.
- Сравнение модификаций учитывает пять новых признаков. WMI group/assembler make
  и manufacturer остаются hints, не удаляя exact Skoda при независимом merge.
  Произвольное противоположное caller-утверждение этим не оправдывается.
- Gateway нормализует vehicle ID тем же `normalize_text` и лимитом, что service,
  сохраняя exact-first, unique alias, точного клиента и отказ до записи при ambiguity.
- Retention index охватывает все состояния фактического DELETE и обновляется у старой
  schema 4. На 32/4096 заданиях VM steps изменились с 639/37215 (`SCAN jobs`) на
  346/346 (`SEARCH`); исходный предел 3x не ослаблен. Это synthetic work, не live latency.

Авторские адресные проверки: Telegram 439 passed, затем только затронутые terminal
ветки 51 passed; automotive 521 passed, после нового binding guard — affected subset
50 passed; CRM 8 passed. Перекрывающиеся прогоны не суммируются как уникальные тесты.
Независимые повторные проверки: Telegram 43 passed и затем 10 terminal cases,
нативные recovery/CAS/no-text-persist/retention probes; automotive 89 tests и затем
41 affected test, 77/77 native binding invariants; CRM 3 Gateway cases и 4 crossrepo
сценария. Эти уточнённые прогоны ловили дополнительные отрицательные случаи до фикса.

Четвёртый crossrepo сценарий исполняет настоящий dispatcher с приватным mock app-server:
CRM persisted/lost response → failed terminal → `needs_review`; direct defer отклонён,
старый event остаётся связанным, новое входящее не создаёт replacement job. Подстановка
исходных unsafe функций только в памяти заставляет новый сценарий падать именно на
автоматическом освобождении, без ручной установки `needs_review`. Сеть запрещена.

Финальная инженерная проверка также обнаружила и устранила две ошибки mypy и превышение
32 KiB entry budget: прежде 45 438 байт уже на `d9e41e8c`. Полные правила общения/сделки
сохранены в самом клиентском skill; убраны дубли и сокращена навигация A1 со всеми
обязательными ссылками. Лимиты документации, code-health и tests не повышались.
Итоговый entry bundle — 32 571 из 32 768 байт; смысловая полнота skill и маршруты A1
проверены независимым ревьюером. Project documentation audit проходит без warnings.
Mypy проверяет 104 source files; native manifest остаётся 72 tools с прежним input schema
fingerprint. Каталоги, graph templates и source pin сверяются по итоговому Manager SHA.

Старая зелёная проверка CRM на `6bc1bbae` не является проверкой нового SHA. Точные конечные
SHA, единственный финальный quality run и image identity/digests сохраняются в техническом
receipt после публикации; GitHub публикация и CI не означают установки.

## Границы доказательств

Нативные воспроизведения проверяют транспортные переходы, field/provenance contracts
и реальные локальные CRM handlers. Они не подтверждают решения произвольной модели,
точность внешних автомобильных данных, fitment, цены/наличие, OCR/визуальное соответствие,
реальную доставку или совместимость установленной системы с новым пакетом.
Windows parser проверялся синтетическими событиями без Windows rehearsal.
Незавершённые старые операции, сторонние WIP и прежние ограничения сохраняются.
