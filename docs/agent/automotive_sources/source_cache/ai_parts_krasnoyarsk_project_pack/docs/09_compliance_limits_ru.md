# 09. Ограничения, законность и допустимая автоматизация

## Зачем этот раздел

Проект должен работать годами. Поэтому нельзя строить его на обходе защит, скрытых парсерах и нарушении правил площадок. Это технически нестабильно и юридически рискованно.

## Разрешено

- Использовать официальные API по договору или публичной документации.
- Использовать кабинеты поставщиков, если это разрешено условиями.
- Генерировать поисковые строки для ручного поиска менеджером.
- Хранить найденные вручную предложения как рабочие заметки.
- Звонить продавцам и фиксировать подтвержденную информацию.
- Использовать карты и справочники через API по лицензии.
- Использовать агрегированную статистику цен, если источник это разрешает.

## Запрещено

- Обходить CAPTCHA.
- Имитировать поведение пользователя для обхода ограничений.
- Массово выгружать объявления без разрешения.
- Использовать украденные cookies, tokens или чужие учетные записи.
- Прятать источник данных.
- Нарушать rate-limit.
- Продавать или публиковать чужую базу объявлений.

## Практическое правило

Если источник не дает официального способа автоматического поиска, система должна работать в режиме:

```text
AI генерирует запросы → человек открывает площадку → человек копирует найденное → AI оценивает и проверяет
```

Это менее автоматично, но устойчиво.

## Как хранить данные объявлений

Хранить только то, что нужно для сделки:

- источник;
- ссылка;
- заголовок;
- цена;
- город;
- продавец;
- телефон, если он открыт и нужен для заказа;
- фото/маркировки, если продавец предоставил;
- дата проверки;
- результат звонка.

Не хранить лишние персональные данные.

## Маркетплейсы: безопасный режим

### Авито

Использовать как канал ручного поиска и официальных инструментов. Если доступен официальный API для конкретного типа аккаунта или интеграции, подключать только по правилам Авито.

### Дром/FarPost

Использовать как канал ручного поиска и официальных инструментов. При наличии API-кабинета или выгрузки прайс-листов использовать только разрешенные методы.

## Источники с API: проверка перед подключением

Перед каждым подключением зафиксировать:

```yaml
source: name
access_type: public_api|contract_api|manual|internal
terms_checked_at: YYYY-MM-DD
allowed_use: ...
forbidden_use: ...
rate_limit: ...
data_retention: ...
contact: ...
```

## Что делать, если источник запрещает нужный сценарий

1. Не обходить запрет.
2. Перейти на ручной режим.
3. Запросить коммерческий доступ.
4. Использовать другой источник.
5. Хранить только пользовательский ввод и результаты звонков.
