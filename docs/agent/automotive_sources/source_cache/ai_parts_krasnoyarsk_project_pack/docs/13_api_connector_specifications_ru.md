# 13. Спецификации коннекторов API

## Общие требования к коннектору

Каждый коннектор должен отвечать на один вопрос: какие предложения есть по заданному артикулу или набору артикулов.

Коннектор не должен:

- выбирать лучший вариант;
- менять бизнес-правила;
- подменять применяемость;
- скрывать ошибки источника;
- нарушать лимиты источника.

## Единый контракт коннектора

```python
class PartsSourceConnector:
    source_id: str
    def search(request: PartRequest, query: SourceQuery) -> list[Offer]: ...
    def healthcheck() -> dict: ...
```

## Forum-Auto

Тип: B2B API.

Назначение: структурированный поиск предложений по артикулу, бренду и кроссам.

Ожидаемые поля ответа:

```text
brand
article
name
price
quantity
warehouse
delivery_days_or_hours
returnable
```

Псевдозапрос:

```http
GET /rest?login={LOGIN}&pass={PASS}&method=listGoods&art={ARTICLE}&cross=1
```

Правила реализации:

- не хранить логин и пароль в коде;
- учитывать лимит запросов в минуту;
- `quantity > 0` не считать финальным подтверждением для срочного заказа без звонка;
- склад и срок преобразовывать в `delivery_days_min/max`;
- возвратность сохранять в `returnable`.

## ZZap

Тип: агрегатор и API статистики/поиска.

Назначение:

- статистика цен;
- регионы;
- первичная проверка рынка по артикулу.

Поля, полезные для модели:

```text
region
price_min
price_med
price_max
used/new filter
instock filter
wholesale filter
```

Правила реализации:

- соблюдать частотные ограничения;
- не использовать API как инструмент массового выкачивания актуальных предложений, если правила это запрещают;
- статистику цен использовать для `market_median`, а не как доказательство наличия конкретного товара.

## Laximo

Тип: каталог/VIN API.

Назначение:

- найти OEM-номер по VIN/Frame;
- получить заменители;
- получить названия и признаки детали;
- проверить применяемость.

Поля, полезные для модели:

```text
detailID
OEM
brand
names
replacements
original
score
saleCategory
```

Правила реализации:

- результат Laximo повышает `fitment_score`, но не дает цену и наличие;
- если VIN не совпадает с применяемостью, блокировать рекомендацию;
- хранить `fitment_basis = vin_oem` или `catalog_cross`.

## TecDoc

Тип: aftermarket-каталог.

Назначение:

- применяемость аналогов;
- параметры деталей;
- кроссы;
- бренды.

Правила реализации:

- использовать как подтверждение аналога;
- не считать аналог равным OEM без проверки условий;
- сохранять параметры детали, если они влияют на выбор: диаметр, сторона, тип тормозной системы, тип подвески.

## 2ГИС

Тип: справочник организаций.

Назначение:

- найти продавцов в Красноярске;
- получить адреса, телефоны, график, сайт, координаты;
- наполнить локальный реестр продавцов.

Пример логики:

```text
query = "авторазбор Красноярск"
city = "Красноярск"
category = "used_parts_yard"
```

Правила реализации:

- не считать 2ГИС источником товарных остатков;
- после нахождения организации создавать задачу звонка;
- обновлять локальный реестр раз в 30 дней.

## Яндекс Карты / Организации

Тип: справочник организаций.

Назначение: аналогично 2ГИС, но как второй источник покрытия.

Правила реализации:

- объединять организации по телефону, адресу и названию;
- не дублировать продавцов;
- не считать найденную организацию надежной без внутренней истории заказов.

## Авито/Дром/FarPost

Тип: маркетплейсы объявлений.

Разрешенный режим:

```text
сгенерировать запросы → человек проверяет → человек вносит оффер → система оценивает
```

Поля ручного ввода:

```text
source
url
title
price
city
seller_name
phone_or_contact_if_needed
condition
photo_marking_received
stock_confirmed
returnable
warranty_days
notes
```

Правила:

- без звонка или сообщения `stock_confirmed = false`;
- без фото маркировки `fitment_basis` не выше `title_match` или `seller_claim`;
- для агрегатов нужен отдельный риск, если нет видео.

## Логистика: Деловые Линии / СДЭК / Почта России

Тип: API расчета доставки.

Назначение:

- рассчитать стоимость доставки;
- рассчитать срок;
- добавить в `expected_total_cost`.

Минимальные входные данные:

```json
{
  "from_city": "Новосибирск",
  "to_city": "Красноярск",
  "weight_kg": 5.0,
  "volume_m3": 0.03,
  "declared_value_rub": 20000
}
```

Если нет веса и объема, использовать оценку по категории, но помечать расчет как приблизительный.

## Логирование

Логировать:

- source_id;
- request_id;
- article;
- время запроса;
- статус;
- количество результатов;
- ошибку, если есть.

Не логировать:

- пароли;
- токены;
- cookies;
- лишние персональные данные.
