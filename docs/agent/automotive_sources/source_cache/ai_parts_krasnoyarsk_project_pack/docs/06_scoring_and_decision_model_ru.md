# 06. Скоринг и модель выбора предложения

## Цель скоринга

Скоринг не должен выбирать «самую дешевую» деталь. Он должен выбрать предложение с минимальной совокупной стоимостью ошибки и простоя.

## Итоговая оценка

```text
score = fitment_score * W_fitment
      + availability_score * W_availability
      + delivery_score * W_delivery
      + price_score * W_price
      + seller_score * W_seller
      + warranty_score * W_warranty
      - risk_penalty
```

Все частные оценки приводятся к шкале 0–100.

## Оценка применяемости

```text
100 = VIN-каталог + OEM совпал + номер подтвержден продавцом
90 = OEM совпал, VIN есть, продавец подтвердил
80 = надежный кросс по каталогу
65 = кросс поставщика без VIN-проверки
45 = совпадение по модели/году/названию
25 = объявление похоже, но нет номера
0 = найдено противоречие
```

## Оценка наличия

```text
100 = звонок сегодня, резерв поставлен, имя менеджера записано
90 = API показывает остаток и склад, источник надежный
75 = API показывает остаток, но склад удаленный
60 = сайт показывает наличие, звонка нет
40 = объявление активно, но продавец не подтверждал
20 = «под заказ», срок неясен
0 = нет подтверждения или продавец не отвечает
```

## Оценка доставки

Для Красноярска:

```text
100 = можно забрать сегодня
90 = доставка сегодня
80 = завтра
65 = 2–3 дня
45 = 4–7 дней
25 = 8–14 дней
10 = более 14 дней
0 = срок неизвестен
```

## Оценка цены

Цену надо сравнивать не со всеми предложениями, а внутри группы:

```text
одинаковый OEM/кросс + одинаковое состояние + сопоставимый срок + сопоставимая гарантия
```

Алгоритм:

1. Собрать цены.
2. Удалить явные выбросы.
3. Рассчитать медиану.
4. Рассчитать отношение цены к медиане.
5. Назначить оценку.

```text
price_ratio = total_cost / market_median
```

```text
100 = ratio <= 0.85, но нет признаков риска
90 = 0.85–0.95
75 = 0.95–1.10
60 = 1.10–1.25
40 = 1.25–1.50
20 = > 1.50
```

Если цена ниже медианы более чем на 35%, добавить риск «подозрительно низкая цена».

## Совокупная стоимость владения заказом

Для сервиса важна не только цена детали.

```text
expected_total_cost = part_price
                    + delivery_cost
                    + payment_fee
                    + delay_days * bay_idle_cost_per_day
                    + risk_probability * expected_rework_cost
```

Где:

- `bay_idle_cost_per_day` — внутренняя оценка стоимости простоя поста/подъемника;
- `expected_rework_cost` — стоимость повторной разборки, возврата, повторной доставки и потери времени.

## Дедупликация

Одинаковые предложения могут приходить из нескольких источников. Дедупликационный ключ:

```text
seller_norm + brand_norm + article_norm + warehouse_city + price_rub + delivery_days
```

Если объявления похожи, но телефоны разные, считать разными продавцами до проверки.

## Категорийные штрафы

### Контрафактный риск

Добавлять штраф, если:

- бренд популярный и цена аномально низкая;
- продавец не дает документы;
- нет упаковки или фото маркировки;
- источник неизвестен.

### Риск б/у детали

Добавлять штраф, если:

- нет фото маркировки;
- нет гарантии;
- нет возврата;
- продавец не подтверждает пробег;
- агрегат продается без видео проверки.

### Риск электроники

Добавлять штраф, если:

- нет аппаратного номера;
- нет программной версии;
- продавец не знает, нужна ли привязка;
- нет гарантии на установку.

## Финальная рекомендация

Отчет должен выдавать не один вариант, а минимум три:

1. Лучший быстрый.
2. Лучший по цене.
3. Лучший сбалансированный.

Для каждого варианта:

```text
- почему выбран;
- что проверить перед оплатой;
- какие риски остались;
- когда последний раз подтверждено наличие;
- кто подтвердил.
```
