# 11. Качество данных и обратная связь

## Проблема

Даже хороший API может дать неверный остаток, срок или кросс. Поэтому система должна учиться на факте: что заказали, что пришло, подошло ли, была ли задержка.

## События жизненного цикла заказа

```text
request_created
candidate_found
candidate_confirmed
order_placed
seller_shipped
part_received
part_installed
part_fitment_failed
part_returned
case_closed
```

## Что записывать после заказа

```json
{
  "request_id": "REQ-2026-0001",
  "offer_id": "OFF-2026-0007",
  "ordered": true,
  "received_at": "2026-05-05",
  "installed": true,
  "fitment_ok": true,
  "delay_days": 0,
  "return_needed": false,
  "seller_rating_delta": 2,
  "notes": "подошло, упаковка нормальная"
}
```

## Как использовать обратную связь

### Продавец

- успешная поставка повышает рейтинг;
- задержка снижает рейтинг;
- неподходящая деталь снижает рейтинг сильнее;
- отказ в возврате снижает рейтинг сильно.

### Бренд

Если определенный бренд часто дает рекламации, увеличивать риск для этой категории.

### Кросс

Если кросс не подошел, записывать связку:

```text
vehicle + part_category + original_oem + cross_article + reason
```

### Источник

Если источник часто показывает неверные сроки, уменьшать `confidence_baseline`.

## Контроль свежести

| Данные | Срок актуальности |
|---|---:|
| цена API | 15–60 минут |
| остаток API | 5–30 минут |
| объявление | до звонка не считается подтвержденным |
| телефон продавца | 30 дней |
| рейтинг продавца | постоянно обновляется |
| VIN-каталог | зависит от поставщика, но кешировать можно дольше |

## Флаги качества

```yaml
data_quality_flags:
  exact_oem_match: true
  vin_checked: true
  seller_confirmed_stock: true
  photo_marking_received: false
  return_policy_confirmed: true
  price_outlier: false
  stale_data: false
```

## Минимальные правила для рекомендаций

1. Для критичной детали нельзя рекомендовать без `fitment_score >= 80`.
2. Для электронного блока нельзя рекомендовать без проверки номера и возврата.
3. Для агрегата нельзя рекомендовать без гарантии и маркировки.
4. Для срочного ремонта нельзя рекомендовать без подтвержденного срока.
5. Для объявления нельзя считать наличие подтвержденным без контакта с продавцом.
