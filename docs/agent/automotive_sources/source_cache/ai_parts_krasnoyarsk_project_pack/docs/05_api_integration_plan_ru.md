# 05. План API-интеграций

## Принцип интеграции

Все источники приводятся к единой модели `Offer`. Коннектор источника не должен решать, что покупать. Он только возвращает структурированные предложения и метаданные свежести.

```text
Источник → Коннектор → Нормализация → Дедупликация → Скоринг → Отчет
```

## Источники для подключения

### B2B API поставщиков

Начинать с тех, где у автосервиса уже есть учетная запись и договор.

Кандидаты:

- Forum-Auto: поиск по артикулу, бренду, кроссам, получение цены, склада, срока и количества.
- Rossko: B2B API при статусе клиента.
- Part-Kom: REST (Representational State Transfer — архитектурный стиль API)-поиск предложений.
- Autopiter: API для участников маркетплейса и заказов.
- Emex, Armtek, Exist/ABC-платформы: проверять условия доступа отдельно.

### Агрегаторы и статистика

- ZZap полезен как источник статистики цен и поиска по артикулу, но его нельзя использовать как источник массового выкачивания актуальных предложений, если это запрещено правилами API.
- ABCP/Docpart/Zaptrade могут быть источниками, если у сервиса есть доступ и разрешение.

### VIN и каталоги

- Laximo: оригинальные каталоги, заменители, кроссы, поиск по VIN/Frame и артикулу.
- TecDoc: aftermarket-каталог и идентификация применяемости.
- OEM-каталоги производителей: использовать через лицензированный доступ.

### Карты и справочники

- 2ГИС API и Яндекс Карты API: не для остатков, а для поиска организаций, телефонов, адресов, графика, сайта и профиля продавца.

### Логистика

- Деловые Линии API, СДЭК API, Почта России API: расчет доставки, сроков и статусов.

## Порядок реализации

### Этап 1. Offline-прототип

- Ввести заявку вручную.
- Подгрузить синтетические офферы.
- Проверить скоринг и отчет.

### Этап 2. Один B2B-коннектор

- Подключить одного поставщика.
- Проверить частоты, авторизацию, обработку ошибок.
- Логировать все ответы без персональных данных.

### Этап 3. Локальная база продавцов

- Собрать CSV (Comma-Separated Values — значения, разделенные запятыми) продавцов Красноярска.
- Добавить категории специализации.
- Добавить журнал звонков.

### Этап 4. Каталоги

- Подключить Laximo/TecDoc или выбранный VIN-каталог.
- Разделить применяемость и наличие.

### Этап 5. Маркетплейсы

- Добавить генератор поисковых запросов.
- Добавить ручной ввод найденных объявлений.
- Добавить проверочный чек-лист звонка.
- Не строить скрытый массовый scraper.

## Rate-limit и устойчивость

Каждый коннектор должен иметь:

```yaml
rate_limit:
  requests_per_second: null
  source_policy: contract_or_public_docs
retry:
  max_attempts: 2
  backoff_seconds: [2, 5]
timeout_seconds: 15
cache_ttl_minutes:
  price: 15
  stock: 5
  catalog: 1440
```

## Обработка ошибок

| Ошибка | Действие |
|---|---|
| 401/403 | остановить источник, проверить ключи |
| 429 | уменьшить частоту, не обходить ограничение |
| 500/502/503 | повторить с backoff (увеличивающейся паузой) |
| нет цены | не включать в скоринг цены |
| нет количества | пометить как неподтвержденное наличие |
| нет срока | требовать звонок или исключить для срочного ремонта |

## Безопасная автоматизация Авито/Дром

Разрешенные режимы:

1. Генерация поисковых строк.
2. Ручной просмотр менеджером.
3. Ручной ввод найденного объявления в систему.
4. Использование официальных API или кабинетов, если доступ предоставлен площадкой.
5. Хранение только нужных для заказа данных.

Запрещенные режимы:

1. Обход CAPTCHA.
2. Скрытая массовая выгрузка объявлений.
3. Использование неофициальных endpoints без разрешения.
4. Имитация поведения пользователя для обхода ограничений.
