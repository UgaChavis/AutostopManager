# 03. Идентификация детали и нормализация запроса

## Почему это главный модуль

Ошибка в поиске запчасти обычно возникает не на этапе цены, а раньше: неправильно поняли деталь, кузов, сторону, двигатель, год выпуска, рестайлинг, комплектацию или номер.

Поэтому агент должен считать заявку неполной, пока не собраны минимальные признаки применяемости.

## Уровни точности заявки

### Уровень A: точный

Есть VIN, оригинальный номер, фото маркировки или номер старой детали.

Пример:

```json
{
  "vehicle": {"make": "BMW", "model": "X5", "body": "F15", "year": 2016, "vin": "..."},
  "part": {"name": "радиатор охлаждения", "oem": "17118625482"},
  "constraints": {"city": "Красноярск", "urgency": "today"}
}
```

### Уровень B: средний

Есть марка, модель, год, двигатель, кузов, но нет VIN и номера.

Пример:

```text
BMW X5 F15 2016 N57 радиатор охлаждения
```

Агент должен искать возможные номера, но в отчете помечать: «требуется VIN-проверка».

### Уровень C: слабый

Есть только бытовое название.

Пример:

```text
Нужен радиатор на BMW X5
```

Агент не должен уверенно проценивать. Нужно запросить уточнения или выдать только ориентировочную карту поиска.

## Обязательные поля заявки

| Поле | Зачем нужно |
|---|---|
| make | марка автомобиля |
| model | модель |
| year | год выпуска или дата производства |
| vin_or_frame | VIN или Frame |
| body_code | кузов: E70, F15, G05 и т. д. |
| engine_code | двигатель: N52, N57, B48 и т. д. |
| transmission_code | коробка, если влияет на деталь |
| drive | привод: задний, передний, полный |
| part_name | бытовое название детали |
| oem_number | оригинальный номер, если известен |
| side | левая/правая, перед/зад |
| condition_allowed | новая, б/у, контрактная, восстановленная |
| urgency | сегодня, 1–2 дня, 3–7 дней, планово |
| city | Красноярск по умолчанию |

## Нормализация артикулов

Артикулы надо приводить к нескольким формам:

```text
11 53 7 509 227
11537509227
11-53-7-509-227
BMW 11537509227
```

Внутренний ключ:

```text
brand_norm + ':' + alnum_upper(article)
```

Где `alnum_upper` удаляет пробелы, дефисы, точки и переводит в верхний регистр.

## Нормализация брендов

Примеры:

```yaml
BMW:
  aliases: ["BMW", "Bayerische Motoren Werke", "БМВ", "Original BMW"]
ZF:
  aliases: ["ZF", "ZF Parts", "ZF Friedrichshafen", "Sachs"]
VAG:
  aliases: ["VAG", "VW", "Volkswagen", "Audi", "Skoda", "Seat"]
```

## Кроссы и применяемость

Кросс не равен гарантированной применяемости. Агент должен различать:

1. OEM replacement (замена оригинального номера производителем).
2. Aftermarket analog (аналог стороннего бренда).
3. Interchange (взаимозаменяемость на рынке, не всегда полная).
4. Marketplace claim (заявление продавца в объявлении).

## Оценка уверенности применяемости

```text
100 = VIN-каталог подтверждает OEM-номер и продавец подтвердил номер
90 = OEM-номер совпал, но VIN не проверен
80 = кросс из надежного каталога, без противоречий
65 = кросс из B2B-поставщика, нет VIN-подтверждения
45 = совпадение по названию/модели/году
20 = только похожее объявление
0 = противоречие по кузову/двигателю/стороне
```

## Красные флаги

- В объявлении нет артикула и фото маркировки.
- Продавец говорит «подойдет точно», но не запрашивает VIN.
- Деталь зависит от комплектации, но комплектация не проверена.
- Электронный блок продается только по номеру корпуса без аппаратной версии.
- Б/у агрегат без маркировки, пробега, гарантии и видео.
- Кузовная деталь без фото креплений.

## Что агент должен делать с неполной заявкой

Если запрос неполный, агент должен построить не финальный заказ, а план уточнения:

```text
1. Нужен VIN.
2. Нужен номер старой детали или фото маркировки.
3. Нужно понять сторону/ось.
4. Нужно подтвердить, новая или б/у допустима.
5. После этого можно проценивать.
```
