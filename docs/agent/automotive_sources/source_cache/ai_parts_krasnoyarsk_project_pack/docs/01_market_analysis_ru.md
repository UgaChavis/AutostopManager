# 01. Анализ рынка поиска автозапчастей в Красноярске и России

## Особенности задачи

Красноярск — крупный региональный рынок, но по многим позициям город уступает Москве, Санкт-Петербургу, Новосибирску, Екатеринбургу и Владивостоку по глубине складских остатков. Поэтому проект должен различать два сценария:

1. срочный ремонт — деталь нужна сегодня или завтра, ценовой оптимум вторичен;
2. плановый ремонт — можно ждать 2–14 дней, ценовой оптимум важнее.

Для автосервиса критично учитывать стоимость простоя. Деталь с ценой выше на 10–25%, но в Красноярске сегодня, часто экономически лучше дешевой детали с доставкой 5–7 дней.

## Сегменты деталей

### Расходники

Фильтры, свечи, колодки, жидкости, ремни, ролики.

- высокая вероятность наличия в городе;
- много аналогов;
- низкий риск покупки по кроссу;
- высокий риск дешевого контрафакта по популярным артикулам.

### Ходовая часть и тормоза

Рычаги, стойки, сайлентблоки, ступицы, суппорты.

- много аналогов;
- важна сторона, ось, комплектация;
- для премиальных авто риск неправильной применяемости выше;
- часто выгодно искать через B2B-поставщиков.

### Кузовные детали

Капоты, крылья, бамперы, оптика, двери, стекла.

- новые неоригинальные детали часто требуют проверки геометрии;
- б/у и контрактные детали часто выгоднее;
- важны цвет, наличие креплений, целостность, фото;
- Авито, Дром и разборки становятся основными источниками.

### Агрегаты

Двигатели, коробки передач, редукторы, раздатки, турбины.

- высокая цена ошибки;
- критичны маркировки, код агрегата, пробег, гарантия, видео проверки;
- обязательно проверять совместимость по VIN и маркировкам;
- итоговый выбор должен учитывать гарантию и возможность возврата.

### Электронные блоки

ECU (Electronic Control Unit — электронный блок управления), TCU (Transmission Control Unit — блок управления коробкой передач), ABS (Anti-lock Braking System — антиблокировочная система), FRM (Footwell Module — модуль пространства ног), FEM (Front Electronic Module — передний электронный модуль), BDC (Body Domain Controller — контроллер кузовного домена).

- часто VIN-зависимы;
- могут требовать кодирования, привязки, клонирования, переноса данных;
- номер корпуса не всегда достаточен;
- нужно проверять аппаратный номер, программную версию, комплектацию, совместимость иммобилайзера.

## Каналы рынка

### Локальные магазины Красноярска

Плюсы: быстро, можно забрать сегодня, проще вернуть, можно договориться о резерве.

Минусы: остатки на сайте не всегда актуальны, ассортимент ограничен, цена может быть выше.

### Федеральные B2B-поставщики

Плюсы: структурированные API, цены, остатки и сроки в одном ответе, можно автоматизировать проценку, удобно для новых деталей.

Минусы: нужен договор, наличие иногда распределено по удаленным складам, не всегда видны фото, риск задержек у транспортной цепочки.

### Агрегаторы

Плюсы: широкий охват продавцов, статистика цен, удобны для первичной оценки рынка.

Минусы: не всегда подходят для массового мониторинга, ограничения API, требуется проверка продавца и фактического наличия.

### Авито, Дром, FarPost

Плюсы: сильны для б/у, контрактных, кузовных, агрегатных деталей, можно найти редкие позиции, есть фото и прямой контакт с продавцом.

Минусы: много дублей, не всегда указан точный артикул, объявления могут быть устаревшими, автоматический массовый сбор может нарушать правила площадки, требуется подтверждение по телефону или сообщению.

### Разборки

Плюсы: хороший источник оригинальных б/у деталей, можно запросить фото маркировок, иногда есть гарантия установки.

Минусы: качество зависит от продавца, сложнее стандартизировать данные, нужен журнал надежности разборок.

## Рыночная логика выбора

### Для срочного ремонта

```text
точная применяемость > физическое наличие в Красноярске > срок получения > гарантия > цена
```

### Для планового ремонта

```text
точная применяемость > надежность поставщика > цена с доставкой > срок > гарантия
```

### Для контрактных агрегатов

```text
маркировка/совместимость > гарантия > подтвержденный пробег/видео > репутация продавца > цена > срок
```

## Основной вывод

Нельзя строить систему только на одном источнике. Эффективная система должна объединять API поставщиков, каталоги, карты и справочники, Авито/Дром, логистические API и обратную связь от автосервиса.
