# Проект для Codex: поиск и оценка автозапчастей в Красноярске и России

## Что нужно построить

Нужно построить прикладную систему поддержки менеджера автосервиса. Система принимает заявку на запчасть, уточняет применяемость, ищет предложения в разрешенных источниках, оценивает риск ошибки и выдает короткий отчет: что купить, где, почему, что надо проверить перед заказом.

Система не должна быть «парсером всего интернета». Она должна быть юридически устойчивой: официальные API (Application Programming Interface — программный интерфейс приложения), договорные B2B (Business-to-Business — бизнес для бизнеса)-кабинеты, ручная проверка объявлений и локальная база продавцов.

## Главная формула

```text
правильная деталь + подтвержденное наличие + приемлемый срок + контролируемый риск > минимальная цена
```

## Требуемый результат реализации

1. Нормализатор заявки.
2. Модуль идентификации детали.
3. Единая модель предложения.
4. Коннекторы к источникам.
5. Система скоринга.
6. Отчет для менеджера.
7. Журнал обратной связи: заказано, подошло, не подошло, возврат, задержка, качество продавца.

## Обязательные ограничения

- Не обходить CAPTCHA, авторизацию, rate-limit (ограничение частоты запросов), robots.txt и технические защиты.
- Не выгружать массово объявления Авито, Дром и других площадок без разрешения.
- Не выдавать наличие как факт без подтверждения.
- Не подбирать VIN-зависимую деталь по неполному описанию, если риск высокий.
- Не хранить персональные данные покупателей и продавцов без необходимости.

## Термины

- VIN (Vehicle Identification Number — идентификационный номер автомобиля).
- OEM (Original Equipment Manufacturer — производитель оригинального оборудования; также оригинальный номер детали).
- API (Application Programming Interface — программный интерфейс приложения).
- SKU (Stock Keeping Unit — складская учетная единица).
- B2B (Business-to-Business — бизнес для бизнеса).
- ETA (Estimated Time of Arrival — расчетное время прибытия).
- SLA (Service Level Agreement — соглашение об уровне сервиса).
