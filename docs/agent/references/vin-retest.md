# Повторный диагностический тест VIN

Стенд вызывается по поручению владельца. Он читает VIN из stdin, использует native
MCP и сохраняет только статусы, коды диагностики, размеры и измерения. Полный VIN,
его хеш, профиль автомобиля, URL провайдера и сырой payload в отчёт не записываются.
CRM, Store и службы стенд не изменяет. База и пакеты не скачиваются.

Перед запуском один раз проверь installed REVISION по A3. Используй Python выбранного
source worktree; изменения source не означают установленный runtime. Стенд читает
полный native tools/list, выбирает summary только по фактической inputSchema и
записывает fingerprint схем. Старые declarations чата не используются.

Из выбранного checkout, с VIN в stdin:

```bash
timeout --signal=TERM --kill-after=2s 65s .venv/bin/python scripts/vin-retest.py --output-dir /var/lib/autostop-manager/private/vin-retest-CURRENT
```

Внешний process deadline обязателен: отмена ожидания SDK не доказывает остановку
сервера или завершение cleanup. После timeout не запускай автоматический повтор;
сверь технический call_id. VIN нельзя помещать в tracked fixture, shell history,
публичный поиск или baseline-файл.

По умолчанию восемь вызовов: inspect, составная расшифровка, PartsAPI VINdecode,
VINinfo, Corgi, брендовые правила, decodeVINus summary и сверка двух результатов.
Независимые вызовы идут параллельно; max_attempts=1 для PartsAPI. После ошибки
переноса или недостающего результата зависимая сверка пропускается. Неизвестные
сетевые счётчики остаются null; известная часть показывается отдельно.
Четыре HTTP ожидаются только при завершённых и измеренных обращениях источников.

`--full-control` — отдельный контроль представления, а не независимое подтверждение.
Он не повторяет empty_result/auth/quota/mismatch/timeout. Для обычного теста full
не нужен. `live-trace.json` и автоматически сформированный `REPORT.md` можно сравнить
с ранее сохранённым обезличенным baseline без чтения всей истории чата.

Время стенда включает live-блок, но не подготовку агента и финальный ответ.
Показывай task_start, первый/последний вызов и report checkpoint отдельно.
Окончательный timestamp ответа доступен лишь после завершения хода; checkpoint
не является полным временем. Не суммируй времена параллельных инструментов.

Полное время прошлого повтора — 702,751 с: 279,442 с до первого live-вызова,
6,835 с между первым и последним вызовами, 416,474 с до финального ответа после них.
Эти исторические измерения не являются скоростью новой версии. Результат источника
partial/unsupported/identifier_mismatch сохраняется как ограничение; успешный HTTP
не означает полной расшифровки или применимости деталей.
