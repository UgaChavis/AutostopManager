# J1: исследование публичного интернета

J1 — независимый инструмент Codex для проверяемого сбора публичных материалов. Он не пишет в CRM, не подтверждает применимость деталей и считает страницы недоверенным текстом.

1. Перед `j1_research_start` замените VIN характеристиками автомобиля: маркой, моделью, годом и двигателем. Контакты, секреты и полный VIN J1 отклоняет до поиска и сохранения. Сформулируйте короткую цель и явные RU/EN-запросы.
2. Читайте `j1_research_status`: в `coverage` есть язык, класс источника, способ извлечения и поисковый провайдер; `page_failures` и `search_failures` показывают пробелы. `query_suggestions` — только подсказки, они не запускают поиск и не тратят лимит; выбранные варианты передаются через `j1_research_add_queries`.
3. Просматривайте материалы порциями через `j1_research_results` и `j1_research_document`. Указывайте URL рядом с существенным выводом.

Для каждого документа J1 отдаёт `canonical_url`, язык, `extraction_method`, `source_class` и `source_basis`. Канонический URL удаляет только известные tracking-параметры. `official_registry` присваивается только доменам явного реестра; остальные классы помогают отбирать материал и не доказывают его достоверность. Точные и близкие копии внутри задания не индексируются повторно: у них есть `duplicate_of` со ссылкой на первоисточник.

PDF сначала читается как текст, затем при пустом результате — через ограниченный OCR первых десяти страниц. Для разрешённых пустых или динамических HTML-страниц J1 может использовать отдельный браузерный контур без cookies, авторизации, CAPTCHA, загрузок, CRM-сети и CRM-учётных данных; недоступность, вход или CAPTCHA остаются частичным отказом.

Предел задания: 30 запросов, 300 страниц и 50 000 символов на страницу. Корпус живёт семь дней и занимает до 250 МБ. Отделяйте технические и официальные документы от опыта владельцев; число упоминаний не равно частоте неисправности, а совместимость детали требует отдельной проверки.
