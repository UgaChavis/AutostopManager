# C2 — CRM MCP-коннектор

C2 связывает Codex с текущей CRM. Выбирай команду по задаче; её точные параметры проверяй в актуальной схеме коннектора. Результат вызова используй для следующего действия или проверки.

## ПОИСК И ЧТЕНИЕ

- `agent_bootstrap` — краткий начальный контекст.
- `agent_board_digest` — список и сводка карточек.
- `agent_search` — поиск карточек, клиентов и других объектов.
- `agent_entity_context` — подробные сведения об одном объекте.

## ДЕЙСТВИЯ С ДАННЫМИ

- `agent_board_workflow` — операции с доской и карточками.
- `agent_finance_workflow` — заказ-наряды, касса и финансы.
- `agent_inventory_workflow` — складские операции.
- `agent_document_workflow` — документы, файлы и печатные формы.

У этих четырёх команд есть внутренние операции. Выбери нужную операцию по текущей схеме команды.

## ДОПОЛНИТЕЛЬНЫЕ ВОЗМОЖНОСТИ

- `discover_raw_capabilities` — поиск дополнительных операций по названию или задаче.
- `get_raw_capability_schema` — текущая схема найденной операции.
- `call_raw_capability` — вызов найденной операции по её схеме.

## ДЛИТЕЛЬНЫЕ ЗАДАЧИ

- `list_agent_workflows` — доступные рабочие процессы.
- `prepare_action_contract` — подготовка контракта действия.
- `start_workflow` — начало процесса.
- `workflow_status` — его текущее состояние.
- `workflow_checkpoint` — сохранение промежуточного результата.
- `workflow_transition` — смена состояния.
- `workflow_wait_for_external` — ожидание внешнего действия.
- `complete_external_step` — завершение внешнего шага.
- `workflow_resume` — продолжение процесса.
- `workflow_cancel` — отмена процесса.

## СОСТОЯНИЕ СОЕДИНЕНИЯ

- `get_connector_identity` — к какой CRM подключён агент.
- `ping_connector` — отвечает ли коннектор.
- `get_runtime_status` — состояние коннектора и CRM.
