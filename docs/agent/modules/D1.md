# D1 — AutoStop Manager MCP

D1 — локальный MCP-сервер инструментов AutoStop Manager. Codex выбирает инструмент по задаче; сервер вызывает функцию или адаптер и возвращает результат. Параметры проверяй в текущей схеме.

## Возможности

- [E1 — Автомобильные данные, запчасти и работы](E1.md): автомобиль, оригинальный номер, аналоги, проверка и рынок.
- [F1 — Адаптер Store](F1.md): поиск и действия магазина, проценки и предложения.
- [J1 — Интернет-исследования](J1.md): публичные источники и отчёт.
- [G1 — Центр автоматизаций](G1.md): задания и готовность.
- `estimate_repair_work_cost` — составная оценка работ; получение источников и отдельный расчёт описаны в [E13](E13.md).
- `prepare_action_contract` — подготовка защищённого действия.
- `parts_store_cards` — работа с карточками CRM о запчастях через Manager.

## Схемы и состояние

Наличие функции в исходниках не доказывает её доступность в работающем сервере. Имена и параметры сверяй через текущий `tools/list`, манифест Manager и [технический справочник](../references/manager-runtime.md). Изменения записей выполняй в пределах поручения с проверкой результата.

Полный paginated `tools/list` native endpoint `http://127.0.0.1:41931/mcp` описывает установленный сервер. Declarations доступных этому ходу инструментов — отдельный срез клиента; старый ход может отставать. Различай endpoint, installed REVISION и текущий client toolset. Reload выполняется только после разрешённой активации, затем проверяется новый ход; ради чтения схемы сервер не перезапускай.

Универсального инструмента поиска и записи памяти [D2](D2.md) среди команд D1 нет. Инструкции и технические заметки читай через [A3](A3.md).

Блокирующие автомобильные read-команды исполняются вне event loop: общий пул
на процесс — два workers и два ожидающих вызова, максимум 60 секунд ожидания.
Busy/timeout возвращают безопасные `error`, `stage`, `adapter_started` и
`adapter_may_continue`, без автоматического повтора. Отмена ожидания не доказывает
остановку потока; его слот удерживается до реального завершения. Статические
правила и сверка готовых данных остаются локальными вызовами.

Синхронные vPIC и каталожные HTTP-чтения имеют общий deadline для заголовков
и тела, лимит размера и два transport workers на процесс. Незавершённый DNS
cleanup удерживает слот после timeout; `provider_transport_busy` не повторяется.
