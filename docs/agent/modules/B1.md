# B1 — Telegram-мост

B1 связывает Codex с [рабочим B2](B2.md) и [личным B3](B3.md) Telegram-аккаунтами. Выбирай нужный аккаунт и команды по задаче; точные параметры проверяй через `--help` текущего bridge CLI.

## ПОИСК И ЧТЕНИЕ

- `dialogs`, `search`, `resolve-phone` — найти диалог или адресата.
- `read --peer ... --limit 20` — начальный пакет сообщений с исходящими. Если для поручения нужны ранее присланные сведения, дочитай разрешённую историю этого же адресата; 20 сообщений не являются пределом контекста.
- `download`, `discard-download` — получить временный файл медиа по текущему target через dry-run/apply и удалить после обработки с проверкой удаления, в том числе после ошибки.
- `monitor-target`, `monitor-read`, `monitor-context` — получить адресата и контекст текущего рабочего события.

`monitor-context` не заменяет `read` с исходящими. Голос рабочего события обрабатывай [monitor-voice wrapper](../../../scripts/run-work-telegram-monitor-voice.sh) с `--event-id ... --language ru` до отправки reply: подготовка голоса требует открытого события. Остальные медиа — [media wrapper](../../../scripts/run-work-telegram-media.sh) с `--delete-after`. Проверяй очистку; credentials/session напрямую не читай.

## ОТПРАВКА

- `send`, `send-photo`, `send-document` — отправить текст, фото или документ.
- `owner-target`, `notify-owner` — определить закреплённого владельца и отправить ему уведомление.

Пишет координатор; субагенты возвращают факты и источники. Отправляй только по разрешённой задаче точному текущему адресату и reply-to. Используй dry-run, затем apply со свежим contract token и устойчивым idempotency key для конкретного эффекта; затем независимо перечитай результат. При неизвестном исходе сначала проверь исходящие, без слепого повтора или смены ключа.

Для `notify-owner` разреши актуальный `owner-target`, используй dry-run/apply, свежий token и один notification key на конкретное событие сделки; проверь доставку. При ошибке привязки или неизвестном исходе не заменяй адресат, ключ или способ отправки. Поводы и содержание клиентских уведомлений определяет скилл, выбранный [B2](B2.md).

## СОСТОЯНИЕ

`probe`, `status`, `owner-status` показывают соединение и настройки. `monitor-status`, `monitor-events` показывают техническое состояние событий без чтения переписки.

CLI, аккаунты и служебные команды: [операционная инструкция Telegram](../references/telegram-runtime.md). Работа с диалогами и медиа: [Telegram skill](../../../.agents/skills/manage-owner-telegram/SKILL.md).
