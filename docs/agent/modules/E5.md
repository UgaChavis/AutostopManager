# E5 — Найти оригинальный номер

E5 помогает найти OEM по автомобилю и запросу на деталь. Выбирай нужные инструменты через D1 в подходящем порядке.

## ПОИСК

- `lookup_original_parts` — план каталожной проверки, кандидаты и недостающий контекст.
- `partsapi_catalog_lookup` — конкретная операция доступного каталога.
- `plan_oem_parts_providers` — выбор источника и маршрута.
- `resolve_vin_oem_parts` — составное исследование по одному каталожному маршруту, если оно подходит задаче.

Учитывай название детали, сторону, положение, известный старый номер и характеристики автомобиля. Сверяй кандидат с каталожным источником и заменами номера. Результат поиска не повышает кандидат до подтверждённого OEM автоматически.

Используй готовность E4 для нужной области поиска. Ошибка привязки ответа VINdecode не запрещает независимый маршрут `getMakes` → `getModels` → `getCars` с уточнением через `getEngine`. Модификацию выбирай по сведениям клиента, фотографий и CRM; каталог сам себя независимо не подтверждает. При нескольких вариантах верни конкретный параметр для уточнения, без выбора первого. При противоречиях двигателя, КПП, привода или модификации допускается лишь разрешённое исследование семейства; точный подбор требует разрешения противоречий. Альтернативные профили нельзя объединять в одну комплектацию. Отсутствующая готовность к записи означает запрет записи.

Передавай уже полученные самостоятельные наблюдения E4 через `identity_observations` в `lookup_original_parts` и `resolve_vin_oem_parts`. Непустой список согласуется без повторного вызова декодеров; `[]` означает явное отсутствие наблюдений и также запрещает скрытое декодирование. При отсутствии параметра или `null` сохранён прежний маршрут совместимости. В `plan_oem_parts_providers` передавай согласованный профиль через существующий `vehicle_identity`: планировщик источники не запрашивает. Проверка привязки к исходному идентификатору и контексту выполняется до каталога; чужие наблюдения не переиспользуются. Это управление расшифровкой, а не сетевыми вызовами каталога: каталожные запросы разрешаются собственными явными флагами и лимитами.

В `resolve_vin_oem_parts` передавай независимые факты через `crm_context`; результат запасного маршрута — `tecdoc_vehicle_fallback` с вариантами и `missing_fields`/`conflicting_fields`. `max_live_calls` общий: прежних 3 вызовов недостаточно, полный маршрут с VINdecode, деревом и деталями требует 6, с getEngine — 7; уточнения могут потребовать больше.
