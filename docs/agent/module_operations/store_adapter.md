# Manager ↔ Store adapter

Проверено по Manager `4e26c6c`, Store `1c4734ac` 2026-09-25. Источник бизнес-данных — Store. Manager держит технический cursor/ack и guarded receipt, не копию каталога или клиентской заявки. Source: `autostop_manager/store_api.py:StoreApiClient`, `store_integration.py:StoreIntegration`, `store_owner_api.py:StoreOwnerApiClient`, `store_quote_conductor.py:StoreQuoteConductor`, `mcp_tools.py:register_manager_tools`. Store: `/opt/autostopapp/backend/app/routers/agent.py`, `docs/store_agent_api.md`, `docs/openapi/store-agent-v1.json`.

## Маршрут и контракт

Codex → Manager native MCP (`http://127.0.0.1:41931/mcp`, streamable HTTP, initialize/ping → `tools/list`) → Manager adapter → loopback `AUTOSTOP_STORE_API_URL` (`/internal/agent/v1`) → Store API → Store PostgreSQL. Owner API uses Store `/api/v1` and отдельный owner principal; CRM интегрируется через документированную private Store API boundary, не через Store DB. Нужны имена переменных `AUTOSTOP_STORE_API_URL`, `AUTOSTOP_STORE_READ_TOKEN`, `AUTOSTOP_STORE_MANAGE_TOKEN`, `AUTOSTOP_STORE_QUOTE_TOKEN`, `AUTOSTOP_STORE_OWNER_TOKEN`, `AUTOSTOP_MANAGER_DB`; значения не печатать. General reads redacted; точное `full` quote read и sourcing требуют scoped token. Полные JSON schemas берутся из активного `tools/list`; source fingerprint проверяется `docs/agent/manager_mcp_catalog.json` и `mcp-probe`.

## Проверка и восстановление

Из `/opt/AutostopManager` безопасный технический probe активной версии: `env PYTHONPATH=/opt/autostop-manager-releases/current .venv/bin/python -m autostop_manager.cli mcp-probe --url http://127.0.0.1:41931/mcp --provider-failure-check --store-check`. Успех: initialize/ping, ожидаемые имена и schemas, `checks.store_runtime_status.ok=true`, `checks.store_owner_capabilities.ok=true`; ошибка source-vs-runtime fingerprint до release означает drift, а не автоматически поломку Store. Тесты из чистого worktree: `AUTOSTOP_MANAGER_ENV_FILE=/dev/null .venv/bin/python -m pytest -q tests/test_store_api.py tests/test_store_integration.py tests/test_store_owner_api.py tests/test_store_quote_conductor.py tests/test_mcp_tools.py`; Store gate: `/opt/autostopapp/scripts/run-backend-tests.sh --agent-write-smoke`, затем `--full`. Тесты synthetic, не доказывают live-provider качество.

Диагностика: проверить точные `REVISION` и Store deploy marker → `systemctl is-active autostop-manager-mcp.service`, `docker inspect` Store health → loopback/private transport и Nginx public deny → `tools/list` schema → отдельные presence-only token checks → principal permission (`401` vs `403`) → `runtime_status`/circuit → Store API response contract → business validation. Не перезапускать сервис по одному provider/auth error. На uncertain apply не повторять запрос: сначала прочитать exact target/receipt. Выпуск Manager/CRM — только через `/opt/autostopcrm/deploy.sh` по [runbook](../deployment_runbook.md); Store — только через GitHub `Deploy VPS` по `/opt/autostopapp/docs/deploy_rollback.md`. При неуспехе использовать соответствующий официальный rollback, сохраняя business volumes и Manager registry.
