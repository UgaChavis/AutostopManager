# Последовательный review AutoStop Manager — 2026-10-13

Охват: исходники Manager, связанные тесты и инструкции. Работа публикуется через проверенные PR в `AutostopManager`; установка серверной версии выполняется отдельным поручением. Исходный checkout и незавершённые пользовательские изменения сохраняются. CRM, Store, VPN и рабочие внешние действия исключены; совместимость проверяется на синтетических данных.

## Забег 001 — автоматизации G1

База: `b8003cd681256dde24c20d14d2d5626ef25a9cc3`. Проверены управление, реестр, расписания, исполнение, outbox, восстановление и удержание выпуска. Проведены первичный review, проверка смежных сценариев и независимая приёмка исправлений.

| ID | Подтверждённая проблема | Исправление |
| --- | --- | --- |
| G1-01 | Timeout или OSError systemctl обходил rollback | Ошибки изменения проходят через существующий откат; ошибка восстановления остаётся явной |
| G1-02 | Смена причины позволяла присвоить активный release hold | Владелец и attempt проверяются при любом изменении release hold |
| G1-03 | Команды внешнего эффекта принимались без revision | `run_now` и `test_notification` требуют актуальную revision |
| G1-04 | Точный status/readiness архивного задания падал | Техническое чтение доступно, мутации архивных заданий запрещены |
| G1-05 | Составные периоды systemd обрезались | Полное точное чтение дней, часов, минут и меньших единиц |
| G1-06 | Одинаковые ключи разных источников сталкивались в outbox | Новые ключи связаны с уникальной командой; старые намерения сохранены |
| G1-07 | Остановка daemon оставляла executor после `stopped` | Текущая работа и её результат завершаются до объявления остановки |
| G1-08 | Известный отказ до send навсегда удерживал digest | Только доказанный stale preview допускает повтор прежнего намерения |
| G1-09 | Ожидание quiescence пропускало потерю hold | Каждый статус проверяет свой release attempt |
| G1-10 | Пропускались или неверно нормализовались окна при переводе часов | Проверяются реальные открытия, повторные часы и исчезнувшие окна |
| G1-11 | Неизвестный период показывался как согласованный | Недостаточное чтение становится `inspection_error` |

Исходные 194 профильных теста проходили; отдельные регрессии воспроизвели перечисленные дефекты. После исправлений профиль G1 проходит 273 сценария, включая чтение архивов, запрет эффектов без revision, сохранение старых outbox-ключей, откат, остановку и восстановление без повторных отправок. Дополнительная проверка 400 расписаний сравнила результат с хронологическим поиском по UTC вокруг смены часов. Независимый review добавил сценарии, когда завтрашнее окно полностью отсутствует.

Общая приёмка: `scripts/release-gates.sh`, затем GitHub CI окончательного PR и основной ветки. Публичные схемы инструментов и версия SQLite сохраняются; отсутствие revision теперь отклоняется согласно уже документированному контракту. Новые ключи outbox относятся только к новым командам. Принудительное завершение процесса и неизвестные отправки остаются отдельными состояниями восстановления.

## Забег 002 — ядро и MCP

База: `efb6ca2ac3bcd7ee62265c8bb4e514f306258fc2`. Проверены native MCP registration,
валидация исходных JSON-аргументов, исполнение синхронных backend, проверка сервера
и общий технический журнал выполнения. VIN-поля проверяются только на границе MCP
с синтетическим decoder; VIN/OEM-реализация и параллельные пользовательские изменения
не входят в этот diff. Изменения общего `storage.py` ограничены транзакциями Manager run ledger.

| ID | Подтверждённая проблема | Исправление |
| --- | --- | --- |
| CORE-01 | Синхронные web и automation callbacks останавливали event loop native MCP | Ограниченные process-wide очереди; управление изолировано от веб-ожиданий, отмена сохраняет слот реального worker |
| CORE-02 | Probe мог зависнуть при ожидании ответа или записи в MCP stream | Полные deadline запросов и session RPC timeout; browser override сохраняется |
| CORE-03 | `tools/list` допускал циклы cursors и бесконечные страницы | Общий deadline, проверка cursor и предел 64 страниц с приёмом последней допустимой страницы |
| CORE-04 | SDK превращал bool и числовую строку в `expected_revision` | Проверка исходного JSON-типа до вызова controller; вложенный payload остаётся совместимым |
| CORE-05 | Строка `"null"` обходила строгие необязательные скалярные поля | Исходный тип четырёх strict полей сохраняется; вложенные options продолжают декодироваться |
| CORE-06 | Manifest принимал bool-count, дубликаты и числовые имена | Проверка исходных типов и уникальности до нормализации |
| CORE-07 | Concurrent external-step dedup возвращал новую step со старой run version | Run, CAS и step читаются в одной write transaction, включая идемпотентный ответ |

Регрессии используют настоящую FastMCP/ClientSession с синтетическими callbacks и
peer в памяти. До исправлений воспроизведены блокировка независимого запроса,
coercion revision/null, пропущенный timeout, неограниченная pagination и смешанная
версия журналирования. Проверяются корректные null/числа, JSON-вложенные аргументы,
заполненная очередь, отменённые ожидающие и выполняющиеся callbacks, независимость
управления, обычная pagination и граница 64 страниц, timeout handshake/call и
конкурентное повторение с CAS и без него. Публичные input schemas, SQLite schema
и действующие ключи идемпотентности сохраняются. Неизвестный исход уже начатого
backend остаётся основанием для сверки результата, без автоматического повтора.
