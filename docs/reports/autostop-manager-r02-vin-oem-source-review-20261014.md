# R02: VIN/OEM — проверка и исправления исходников Manager

Дата: 2026-10-14. База: `45db65a3b6f0cec42cbb420d0bc608dad03e4d2b`.
Объём: 13 подтверждённых групп, P1 × 2 и P2 × 11. Это авторская проверка кандидата;
независимая приёмка, полный release gate и CI опубликованного SHA выполняются отдельно.

| ID | Приоритет | Подтверждённая ошибка | Исправление |
| --- | --- | --- | --- |
| R02-01 | P2 | Очередь выбранного decoder запускала новый бюджет после dequeue и не ограничивала локальные admissions | Исходный монотонный deadline передаётся через ContextVar. Dedicated pool допускает 2 workers + 2 ожидающие заявки. Abandoned/expired строки не начинают decoder; admission освобождается только при фактическом завершении. Начатый sync worker сохраняет слот, неизвестное число сетевых вызовов обозначается явно. |
| R02-02 | P2 | Огромный integer технического поля ронял весь E2 batch | Переполнение даёт обычный invalid_input одной строки. Соседние строки, порядок, количество и закрытая готовность ошибочной позиции сохранены. |
| R02-03 | P2 | Малый положительный остаток превращал весь batch в invalid_input и терял уже выполненные строки | Внешний минимум проверяется один раз. Нехватка внутреннего остатка даёт deadline_exceeded соответствующей строки, сохраняя результаты и измерения завершённых строк. |
| R02-04 | P2 | Общий факт первым скрывал конфликт конкретных КПП или рынков | Проверяются все пары наблюдений. Противоречие специфических значений сохраняется при любом порядке, full/summary и повторной сверке. |
| R02-05 | P2 | Сверка теряла transmission_speeds и его конфликт | Число передач — отдельный типизированный факт со статусом и происхождением. Поддержана прежняя числовая строка основного E2/vPIC результата; конфликт 6/8 не исчезает. |
| R02-06 | P2 | Malformed supplied поля становились canonical/supported | Применяются проверки строк, годов, дат, options, чисел и числа передач. Ошибочное поле исключается из canonical profile, исходный вариант и причина сохраняются. |
| R02-07 | P2 | Независимый vPIC возвращал raw keys/VIN, теряя факты при сверке | Профиль использует canonical E2 поля и безопасную публичную проекцию. Binding, lineage и diagnostics сохранены; нечистая диагностика и эхо подсказки года не повышаются до supported. |
| R02-08 | P2 | Правильный low-volume WMI на шесть символов отвергался; V1 ошибочно маскировал WMI-ключ | WMI сверяется по нормализованному VIN и правилу позиций 1–3 + 12–14. Публичный 3/6-character ключ сохраняется целиком и проходит реальный endpoint parser → decode → reconcile. Факты остаются только manufacturer-family, без engine/year точного VIN. |
| R02-09 | P1 | Broad совместимость ошибочно подтверждала конкретное условие fitment | Проверка направлена от известного факта к требуемой конкретности. Automatic без числа передач, ROW и семейная модель не подтверждают более конкретное условие. Известное число передач уточняет тип КПП. |
| R02-10 | P1 | Неизвестные keys диапазона игнорировались при exact fitment | Диапазоны принимают только from/to. Дополнительный key даёт unknown/missing как в caller criteria, так и в source conditions. Новые операторы не внедрялись. |
| R02-11 | P2 | Префикс чужого OEM номера или склейка полей давали ложную веб-ссылку | Проверяются границы полного номера внутри каждого поля и компонента URL. Допустимое оформление сохраняется; prefix/suffix/word fusion не подтверждают номер. Ссылка остаётся в результате, fitment_confirmed=false. |
| R02-12 | P2 | Подготовка sync/async batch теряла происхождение copied provider facts, включая сохранённые вложенные факты при blank внешних полях | Provider/primary lineage, обычный/компактный JSON профиль и field provenance сохраняются через подготовку. Blank outer не перекрывает реальный источник; непустой explicit override сохраняет приоритет. Копия PartsAPI не становится независимым CRM фактом. |
| R02-13 | P2 | Array/object source.part_number конкатенировался в ложный OEM; boolean True связывался с номером TRUE | Коллекция и boolean не связываются с одним номером в capture/fitment. Существующая numeric-scalar политика, включая integer 1234, сохранена. |

Для начатого sync read при timeout `execution.network_calls=null` означает неизвестный
счётчик, `network_calls_lower_bound` сохраняет известную сумму; upstream cancellation
не утверждается. Синхронный библиотечный API продолжает ждать уже выданный decoder
в пределах его собственного timeout. У не начавших decoder строк сетевых вызовов ноль.

ограничение manufacturer-family, VIN privacy и остальные исправления сохранены.
